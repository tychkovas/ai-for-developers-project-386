# API-контракт как артефакты без живого бэкенда

Шаги 3–6 курса требуют TypeSpec-контракт, генерацию OpenAPI, клиентский SDK
и серверные артефакты — это противоречит ADR-0001 («бэкенда не существует
и не планируется»). Владелец выбрал трактовку: **контракт как артефакты**.

TypeSpec описывает модели и эндпоинты домена (типы события, слоты, записи)
по утверждённой спецификации (`docs/spec/app.md`) — не для живого сервера,
а чтобы сгенерировать из него `docs/openapi.yaml`, строгие типы для
фронтенда (шаг 4) и серверные артефакты (шаг 5). Ничто не обслуживает
этот контракт по HTTP: приложение остаётся SPA на `localStorage` (ADR-0001
в силе для рантайма).

## Consequences

- `spec/main.tsp` — исходник контракта, `docs/openapi.yaml` — сгенерированный
  артефакт (коммитится), генерация — `make openapi`.
- Контракт зеркалит внешнее поведение спецификации и служит входом для
  генераторов шагов 4–6; если позже появится живой бэкенд — он реализует
  этот контракт, а не новый.
